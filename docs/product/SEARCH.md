# Permission-scoped workspace search

The release coordinator confirmed this additive migration applied to owner-only staging at approximately 01:52 UTC on 20 September 2026. Hosted application UI/HTTP acceptance remains a separate release check. Migration `20260920012510_product_workspace_search.sql` is additive; it does not edit any applied migration. Search supports only the existing command drawer entities: families, children, leads, classes, trials and assigned coach sessions.

`GET /api/search` uses the current cookie session and account context, then calls the invoker RPC `workspace_search`. Parameters are `q` (2–80 trimmed characters), `kinds` (supported comma-separated entities), `limit` (1–50, default 20), `after` (the prior `next_cursor`), and optional `branch`/`child` UUID narrowing. Response: `{items, total, next_cursor}` within the usual service envelope. `total` is the exact currently authorized matching count before cursor slicing; it includes records outside workspace transport pages. Search is a literal case-insensitive substring over the same title/detail fields the prior drawer used, so `%` and `_` are not wildcards. It does not search private notes, telephone numbers, documents or arbitrary tables.

All ordinary candidate tables, snippet joins and counts use the caller's existing RLS under an invoker function. The only definer helper projects existing coach-session metadata using current role, assignment/substitute, branch, MFA and time-window checks. Search itself returns no roster. Pagination orders by entity kind and UUID under the fixed C collation; the cursor is a position, never a capability. Every request rechecks current authorization. Results are live rather than a historical snapshot; concurrent inserts/deletes can change the count or pages. The drawer replaces each page instead of retaining previously authorized snippets, cancels stale requests on query/scope changes, and displays failures separately from zero matches.

`GET /api/search/record?kind=...&id=...&offset=...` hydrates one destination through the same current cookie/RLS client, never the service key. A child search's `record` is its family UUID, matching existing family navigation. Missing/revoked primary records return 404. Families return scoped children, sport profiles and enrollments; leads return activities, enquiries and bookings; classes return sessions and permitted roster; trials return bookings/sessions. Related collections each return at most 100 rows, with `{offset,total,next_offset}` per table; they are not silently complete. The targeted session RPC returns the existing coach projection for one currently authorized session beyond the old 200-session transport cap. Cancelled sessions omit students; current roster/assignment checks remain unchanged.

`hydrateSearchRecord` and `workspaceSearch` in `lib/platform/search.ts` are typed client adapters. `readWorkspaceSearch` and `readSearchRecord` in `search-server.ts` validate parameters and use the request-scoped database client. `PortalShell` forwards the selected entity kind with the existing navigation target; workspace integration owns merge, related-page loading and URL reload behavior.
