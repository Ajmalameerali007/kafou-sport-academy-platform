# Connected product interfaces and access

This augments the existing foundation and Phase 2 API. The same private staging application, cookie session and PostgreSQL authority serve every workspace. No provider credentials are returned to browsers. Tables and generated fields are documented in `lib/platform/database.types.ts`; the accepted command shapes are executable Zod contracts in `lib/platform/`.

## Routes and deep links

Public URLs remain `/`, `/trial`, `/auth`, `/auth/confirm` and `/auth/reset`. Authenticated workspaces remain `/account`, `/admin`, `/branch`, `/sales`, `/coach`, `/parent`. Unknown URLs retain the branded not-found experience. Modules are meaningful query-state views rather than separate pretend dashboards: `?view=Schedule`, `?view=Finance`, `?view=Progress`, and so on. Parent child context uses `?child=<authorized UUID>` and survives reload/back navigation without putting personal information in local storage.

A displayed module does not grant permission. For example, Head Office financial and broadcast actions need the corresponding explicit grants. Sales has neither a family directory nor financial/attendance authority. Coach attendance is read-only unless the current assignment and explicit `attendance.finalize` grant both permit it.

## Same-origin endpoints

| Endpoint                                                                     | Purpose and boundary                                                                                                                                                                                                                                  |
| ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Existing `/api/auth/*`, `/api/workspace`, `/api/commands`, `/api/operations` | Existing verified cookie authentication, account context, family/lead/trial/scheduling boundaries retained                                                                                                                                            |
| `GET /api/product?offset=0`                                                  | RLS-filtered module records in batches of 200; `product_pagination.more` is explicit. User-scoped coach/family projections do not broaden base-table permissions. A failing domain returns a failed response rather than a successful empty dashboard |
| `POST /api/product`                                                          | `{action, data, key}`. UUID key plus actor, payload fingerprint and current protected-access fingerprint; response only after transaction commit. Protected read previews always reauthorize and are not cached                                       |
| `GET /api/makeups?credit=<UUID>`                                             | Authorized current credit and compatible replacement availability; commit rechecks all constraints                                                                                                                                                    |
| `GET /api/product/certificates/<UUID>`                                       | Authorized, unrevoked actual PDF, `private, no-store`. Missing/unauthorized records do not expose names                                                                                                                                               |
| `GET /api/product/receipts/<UUID>?locale=en\|ar`                             | Real authorized receipt PDF with current allocations/refunds, protected by current family/branch finance access and no-store                                                                                                                          |
| `GET /api/product/reports/<UUID>?locale=en\|ar`                              | Exact published report version as EN/AR PDF; drafts denied to all exporters, current record access rechecked                                                                                                                                          |
| `GET /api/search?q=...&kinds=...&after=...`                                  | Literal bounded search, exact current-scope counts and keyset pagination; RLS includes snippets and known IDs                                                                                                                                         |
| `GET /api/search/record?kind=...&id=...&offset=...`                          | Authorized selected destination and independently paged related records, including results beyond the workspace batch                                                                                                                                 |
| `POST /api/files/upload`                                                     | Authorized family/optional child and branch, server-generated object path, bounded PDF/PNG/JPEG bytes, MIME signature and SHA-256 checks. No arbitrary path or public URL                                                                             |
| `GET /api/files/<UUID>`                                                      | Current metadata/RLS authorization and logged download attempt before exact private object read. Withdrawal takes effect on the next request                                                                                                          |

Mutation requests require the configured same origin; user session and active permissions are checked at API and transaction boundaries. Sensitive endpoint rate limits persist in PostgreSQL. Result codes distinguish validation, unauthenticated, forbidden, not_found, conflict, rate_limited and unavailable. Authenticated responses are uncached.

Command families: `commercial.*` (exact-minor-unit records and entitlement ledger); `academy.*` (makeups, corrections, delivery, substitutes, waitlists); `schedule.*` (previewed occurrence changes and reviewed transfers); `coach_attendance.*` (explicitly granted assigned-coach attendance only); `development.*` (draft/review/publish, reports, certificate/reversal, safety); `community.*` (family access, support, documents, handover, private recognition); `engagement.*` (rules, noncash rewards, referrals); `events.*` (atomic one-off sibling registration); `communication.*` (in-app recipient preview and scheduled manual dispatch); `files.withdraw`; `permission.*` (Owner/AAL2 only).

The low-level `academy.session.move` is deliberately rejected at the public dispatcher. Use `schedule.move`; it reconciles entitlement reservations and validates the full affected occurrence set atomically. New commands use the existing academy-wide transaction advisory lock. No throughput claim is made from small synthetic concurrency tests.

Current records—not public metadata or a staff selector—grant authority. Guardian revocation, family-branch unlinking, changed role/branch grants, account suspension and substitute expiry are rechecked. Cached write responses cannot retain an obsolete authorization snapshot. Downloads, search snippets and counts use the same authorized data, not a privileged universal cache.

## Operational limitations and activation

The generated PDF and private document byte round-trip were exercised locally. Private documents are limited to 512KB, with no malware-scanning/compliance claim; use synthetic content only. One-off events do not imply a paid multi-day camp or event attendance engine. The communications queue produces actual in-app notifications; external channels remain `not_configured`, and scheduled dispatch currently requires an authorized operator. Online provider settlement, telephony, hosted SMTP, real owner activation, production policies/residency and Mindbody import remain separate gates. See FEATURE-MATRIX and ACTIVATION-REGISTER for exact boundaries.
