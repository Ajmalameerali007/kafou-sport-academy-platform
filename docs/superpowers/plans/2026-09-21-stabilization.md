# KAFOU stabilization execution plan

Approved scope: user stabilization brief, 21 September 2026. Continue inline using the existing operational application. No public-site redesign, provider activation, hosted changes, data reset, or fixture renaming.

## Preserved baseline
Source archive, binary diff, Git status, private database dump, schema statement hashes and live preflight are under outputs/stabilization-2026-09-21. Base commit is insufficient to identify this dirty checkout.

## Design
- Parent Family: child-first cards with full names accessible in profile panels, recorded age, assessed sports and membership state. Contact editing, adding a child and safeguarding remain available through focused disclosures/panels.
- Parent Membership: paginated server summaries scoped to the explicitly selected child. Current/history distinction, complete entitlement and invoice totals, explicit missing-data state. Renewal opens one review panel with exact sold offer, child, branch, period, terms and price. Existing immutable offer/renewal rules remain authoritative; unavailable offers are not silently substituted.
- Packages: server-searched catalogue with one row/card per package, compact complete branch counts and price range. A separate searchable assignment editor preserves unassigned versus disabled states. Missing configuration is actionable and not given fabricated defaults.
- Shared async reads: scope key prevents old data appearing under new headings; polling/focus refresh rechecks server permissions. Target visible changes within two seconds locally. Do not interrupt dirty forms; clearly identify updates awaiting review.
- Calendar: server date-window query, bounded paging and explicit incomplete/error states rather than filtering the first workspace batch.

## Execution slices
1. Reproduce supplied screens and record before screenshots. Add failing read/role and UI regression cases.
2. Add RLS-respecting complete projections. Reuse existing commands and immutable commercial history. Test on restored disposable database before additive local migration.
3. Implement parent and package presentation with localized copy and accessible detail panels. Preserve existing edit paths.
4. Query/synchronization audit: date windows, pagination, stale responses, already-open revoked sessions; test separate browser contexts.
5. Run current domain/security tests, typecheck, lint, build. Freeze fingerprint, repeat browser scenarios and capture desktop/mobile EN/AR. Inventory unverified routes/actions and any unresolved business policies separately.

## Acceptance boundaries
Local browser emulation is not physical-device verification. Offline records are not transfers. In-app notifications are not external delivery. Synthetic records remain labeled and preserved. No claim of full stabilization until all A–H acceptance scenarios have current evidence.
